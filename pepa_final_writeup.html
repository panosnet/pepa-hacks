Chapter 1

SSH Access

Dustfab builds Valetudo firmware with a unique per-build ed25519 SSH key. The matching private key gives full root access wirelessly, no UART, no hardware hacking needed.

Architecture

WatchDoge (supervisor) → rr_loader (navigation + librrnavdrv.so) → RoboController + AppProxy. Kill any process — WatchDoge restarts in ~2s. The key insight: rr_loader loads shared libraries from /etc/ld.so.preload on every restart.

Chapter 2

Reverse Engineering the Speed Limit

No config file controls wheel speed. The limit is baked into /opt/rockrobo/cleaner/lib/librrnavdrv.so — a 3.2MB stripped ARM shared library. Downloaded to Mac, parsed the ELF dynamic symbol table in Python to locate 188 speed-related exports.

Disassembled the 12-byte getters in ARM Thumb2 by hand:

NavConfig::Robot::Get_MAX_SPEED() @ 0x2aadc9ARM Thumb2
4801  ldr   r0, [pc, #4]    ; load literal → r0 = 0x308e08
4478  add   r0, pc           ; add PC-relative base
3020  adds  r0, #0x20       ; r0 = 0x308e28  ← pointer to float constant in .text
4770  bx    lr              ; return const float& (C++ reference)

Hexdump of the constants at those offsets:

offset bytes value 0x308e28: 9a 99 99 3e = float 0.30 ← MAX_SPEED — patched 0x308e34: 33 33 b3 3e = float 0.35 ← LIMIT_MAX_SPEED — patched

Disk patch — /opt is writable, 8 bytes changed with dd conv=notrunc:

# float 0.5 = 0x3F000000 → LE: 00 00 00 3f
root@rockrobo:~# cp $LIB /mnt/data/librrnavdrv.so.orig  # backup first
root@rockrobo:~# printf '\x00\x00\x00\x3f' | dd of=$LIB bs=1 seek=$((0x308e28)) conv=notrunc
root@rockrobo:~# printf '\x00\x00\x00\x3f' | dd of=$LIB bs=1 seek=$((0x308e34)) conv=notrunc
root@rockrobo:~# kill -9 $(pgrep rr_loader)  # WatchDoge restarts with new values
Chapter 3

LD_PRELOAD Speed Override — 4 Versions to Get Right

The disk patch changes the baseline speed but requires a restart to apply. For live changes, we inject a shared library via /etc/ld.so.preload. Every process (including rr_loader after WatchDoge restarts it) loads our library first, letting our symbols shadow librrnavdrv.so's.

v1

Config getters only — ❌ Didn't intercept

Overrode NavConfig::Robot::Get_MAX_SPEED() etc. Library loaded but symbols weren't in the dynamic symbol table (.dynsym was empty). BusyBox nm -D returns nothing; confirmed via objdump -T on your build PC. Built with Fedora's arm-linux-gnu-gcc using stub libraries — stubs didn't properly export symbols.

v2

Config + GoStraight getters — ❌ Still no interception

Added NavConfig::GoStraight::Get_MAX_SPEED() and all config getters. Rebuilt with proper -fPIC -shared flags; objdump -T on your build PC showed GLOBAL symbols in .dynsym. But speed test showed no change — these functions are likely not called via PLT (may use direct relative calls within the library), so LD_PRELOAD can't intercept them.

v3

SetSpeed motion interceptor — ✅ Speed works, ❌ SLAM broken

Intercepted NavRRLoaderPlugin::SetSpeed(double lin, double ang) via dlsym(RTLD_NEXT) and multiplied lin × scale. Robot visibly moved faster. But the nav planned sweeps at 0.3 m/s while the robot executed at 0.45 m/s — SLAM saw unexpected extra movement, map drifted and robot got confused.

v4

WallFollower planning speed override — ✅ Works correctly

Overrode NavConfig::WallFollower::Get_SPEED() — the function that controls how fast the nav plans the zigzag cleaning sweeps. Nav plans at the new speed → calls SetSpeed at the new speed → robot executes at that speed. Plan == execution → SLAM stays accurate. SetSpeed passes through unchanged.

/mnt/data/speed_override.so — v4 final implementationC + ARM hard-float
/* Reads desired speed from /mnt/data/speed.conf on every call */
static float get_speed_f(void) {
    FILE* f = fopen("/mnt/data/speed.conf", "r");
    if (!f) return 0.45f;
    char buf[32] = {0}; fgets(buf, 32, f); fclose(f);
    if (!strncmp(buf,"slow",  4)) return 0.20f;
    if (!strncmp(buf,"normal",6)) return 0.30f;
    if (!strncmp(buf,"fast",  4)) return 0.45f;
    if (!strncmp(buf,"turbo", 5)) return 0.55f;
    if (!strncmp(buf,"ultra", 5)) return 0.65f;
    if (!strncmp(buf,"max",   3)) return 0.80f;
    return 0.45f;
}

/* === Override planning speeds (called via PLT — LD_PRELOAD works here) === */
float* _ZN9NavConfig12WallFollower9Get_SPEEDEv(void* t)  { g=get_speed_f(); return &g; }
float* _ZN9NavConfig17WallFollowerTANOS9Get_SPEEDEv(void* t) { g=get_speed_f(); return &g; }
float* _ZN9NavConfig10GoStraight13Get_MAX_SPEEDEv(void* t)  { g=get_speed_f(); return &g; }
float* _ZN9NavConfig5Robot13Get_MAX_SPEEDEv(void* t)         { g=get_speed_f(); return &g; }
/* ... (+ 5 more planning speed getters) */

/* === SetSpeed passes through unchanged — nav already planned correctly === */
void _ZN17NavRRLoaderPlugin8SetSpeedEdd(void* t, double lin, double ang) {
    static void (*orig)(void*, double, double) = 0;
    if (!orig) orig = (void(*)(void*,double,double))dlsym(RTLD_NEXT,
        "_ZN17NavRRLoaderPlugin8SetSpeedEdd");
    if (orig) orig(t, lin, ang); /* unchanged — SLAM stays accurate */
}

Why v4 fixes SLAM: Nav plans sweep rows at the new speed (e.g. 0.55 m/s turbo). Nav then calls SetSpeed(0.55). Robot executes at 0.55. SLAM sees planned = actual = consistent. No drift.

Compiled on your build PC (Fedora 41) using Ubuntu 16.04 in podman — the only way to get glibc-2.19-compatible ARM binaries. Deployed via HTTP server (the only reliable transfer method).

⚠ Critical: symbol visibility

The .so must have functions in the dynamic symbol table (.dynsym). Compile with -fPIC -shared only. Verify with objdump -T speed_override.so | grep GLOBAL on a machine with proper tools — BusyBox nm -D returns nothing even for valid .so files.

Live speed changes

Changing speed writes speed.conf and sends app_pause → 1.5s delay → app_start via the miio named pipe. GoStraight re-reads the planning speed on resume via our overridden getters. Brief cleaning pause, then continues at new speed.

⚠ Critical: process group killing

Kill the radio shell pipeline by process group: process.kill(-pid, "SIGTERM"). Killing only the shell PID leaves mpg123 and alsa_play running as orphans, holding the ALSA device. Next station start fails with "device busy".

Chapter 6

Volume Control

ALSA amixer scontrols returns empty — no mixer controls. Valetudo's SpeakerVolumeControlCapability PUT returns 400 (firmware doesn't support miio volume writing). Solution: mpg123's --scale flag scales PCM before output. The wrapper script converts 0–100% → scale 0–32768:

/mnt/data/mpg123 — volume wrapperShell
VOL=$(cat /mnt/data/radio_volume.conf 2>/dev/null | tr -cd '0-9' | head -c 3)
[ -z "$VOL" ] && VOL=50
SCALE=$(( VOL * 328 ))          # 100% → 32800 ≈ 32768 max
exec /mnt/data/mpg123_bin --scale $SCALE "$@"

The Radio card's volume slider calls PUT /api/v2/robot/radio/volume which writes radio_volume.conf and restarts the current stream (~600ms gap). Volume persists across reboots.

Lessons Learned

What Burned Us — So It Doesn't Burn You

💀

SSH pipe binary transfer = corruption

Piping cat binary through two SSH connections silently corrupts files. Always: HTTP server on your build PC (port 9999) + wget on robot to /mnt/data/. Verify with MD5.

🪣

/tmp is only 30MB

Robot's /tmp is a 30MB tmpfs. Large file downloads fail silently with wget exit 3. Always download to /mnt/data/ (1.2GB free).

🐍

Python heredoc \n breaks JS

"\n" in a Python ''' string becomes a literal newline in the JS, creating an unclosed string literal. Binary compiles, crashes at startup. Use string concatenation.

📦

pkg build cache = stale binary

Always rm build/armv7/valetudo* before rebuilding. Build frontend and backend as separate steps with explicit --user root.

💥

Starting Valetudo from SSH = EPIPE crash

Valetudo's IPC pipe to rr_loader breaks when SSH session closes. Only system reboot reliably starts everything in the right sequence.

👻

Kill shell PID ≠ kill pipeline children

Killing sh -c "mpg123 | alsa_play" by PID leaves both child processes running. Kill by process group: process.kill(-pid, "SIGTERM").

👁

LD_PRELOAD .so needs exported .dynsym

Library loads but intercepts nothing if symbols aren't GLOBAL in .dynsym. BusyBox nm -D always returns empty — verify with objdump -T on your build PC.

🗺

Scaling SetSpeed breaks SLAM

Multiplying the velocity command causes nav-planned position ≠ actual position. Override the planning speed functions instead so nav plans and executes consistently.

📡

Greek radio is geo-blocked or AAC-only

Many Greek streams timeout from non-Greek IPs, or use AAC that mpg123 1.26.4 can't decode. Test with: wget -O - URL | mpg123_bin -s - | wc -c — result >1000 = works.

✅

Ubuntu 16.04 for glibc 2.19 compat

Robot has glibc 2.19. Ubuntu 22.04 gcc generates GLIBC_2.28+ symbols. Ubuntu 16.04 (glibc 2.23) stays compatible. Always verify with objdump -p binary | grep GLIBC.

✅

HTTP server is the only reliable transfer

gzip on your build PC + HTTP server on port 9999 + wget from robot. Always verify size and MD5 after transfer. Never rely on SSH pipe for binaries.

✅

Radio Browser API for verified stream URLs

de1.api.radio-browser.info/json/stations/search?name=X&countrycode=CZ. But always test FROM THE ROBOT — geo-blocking exists. The decode test is the definitive check.
